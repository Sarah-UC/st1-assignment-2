# Reflection

Before using AI, I built a simple SmartCare appointment prototype using Python. I first stored appointment details using variables and then improved the program by using a list, dictionaries, and functions. I was able to run the program and identify some limitations, such as not checking all the appointment details.

AI helped me understand my code better, especially how the list and dictionary work together to store multiple appointments. It also helped me identify limitations that I had not considered, such as duplicate appointments and the fact that the data is lost when the program stops.

The AI did make some assumptions. For example, it assumed that a simple list was enough for storing the appointments and did not add input validation unless requested.

I verified the AI-generated code by running it and testing different inputs, including a normal appointment, a blank patient name, duplicate appointments, and `None` values. This helped me see what the code actually did instead of simply trusting the AI's explanation.

The engineering work still remained with me. I had to understand the code, compare it with my own version, test its behaviour, decide what improvement to make, and make sure I could explain the final code myself.
